# Card addresses and related links

Location/address text occupies a distinct local map-icon row with a native new-tab anchor to a saved validated Google Maps destination or selected OpenStreetMap coordinates. Otherwise it uses an encoded ordinary Maps search for the plan's name/address. Constructing/displaying the URL makes no Places request and invents no Place ID. An identical footer Maps action is consolidated into the address row. Multiple destinations remain separately labelled; none arbitrarily takes over the entire address. Explicitly omitted locations stay plain text and missing location text produces no row, without a decorative arrow or misleading icon.

Saved links and safe raw/Markdown destinations from the plan's prose share a compact wrapping icon-link group. This is a [render-only projection](card-text-links.md): stored fields and editor bounds remain unchanged, explicit labels and order are retained, and identical validated destinations share one action. Icons are inline SVGs with visible text labels; no favicon or metadata request is made.

Plans may have `relatedLinks`, an ordered array of at most six user-authored objects with a stable `id` (1–80 letters, numbers, underscores or hyphens, starting with a letter/number), nonempty `label` up to 80 characters and absolute HTTP/HTTPS `url` up to 2048 characters. IDs are unique within the plan. Send `[]` to clear; omitting the field in `upsert_plan` preserves it. Labels are escaped text. Translation patches cannot replace links.

The editor offers labelled inputs and Add, Remove, Move up/down buttons, focus retention and live ordering/removal announcements. Owners, content managers and current trip creators use normal version checks, atomic transactions and durable request IDs. Joined read-only members can open links but cannot edit them. A stale editor retains its draft and reports the existing conflict; reopen against the new version to reconcile. HTTP, MCP, create, replacement and import/export share validation. Entries survive polls, reloads and restarts. The legacy generator validates and preserves them too.

Relative URLs, unsafe schemes, userinfo (including empty userinfo), malformed hosts/ports/percent escapes, literal or encoded controls/backslashes and invisible formatting are refused. Native click, Enter, modifiers, middle-click and touch/long-press semantics are preserved without scripted opening. External links retain `target="_blank"` and `rel="noopener noreferrer"`. The refresh-during-press guard covers related/fallback address links. Physical-device context menus and long-press still require acceptance.

No database migration or trip rewrite occurs on upgrade. Earlier trips without the optional field are unchanged. An old validator rejects writes to trips carrying new entries: do not blindly revert to an earlier write-capable release after users add links. Retain the accepted image or a tested compatibility rollback with the new validator. Never restore an old database or allowance ledger over later edits/usage.

`npm run test:related-links` exercises fictional HTTP, SQLite, official MCP SDK and DOM paths: unsafe inputs, ordered IDs, conflicts/retries, import/export/restart, isolation, permissions, editor controls and refresh races. Full regression, generation/static QA and browser evidence belong in the checkpoint; this procedure alone is not a passing-run claim.
